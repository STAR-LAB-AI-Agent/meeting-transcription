# 实验报告

## 1. 实验名称

AI 会议语音转写与检索智能体（《智能体开发实战》第 15 题）

## 2. 实验目的

1. 掌握基于 FunASR 的会议音频带时间戳转写；
2. 实现关键词检索、时间定位、自动会议摘要；
3. 掌握“Agent → Skill → Script/CLI → 模型”的分层设计；
4. 落实最小权限安全、日志脱敏与低 Token 优化。

## 3. 需求分析

用户需要把会议录音快速转为可检索、可定位、可总结的文字资料。核心需求：
音频转写（带时间戳）、关键词检索（带上下文）、时间点/区间定位、自动摘要，
并通过统一接口供 Agent Runtime 调用。

## 4. 系统总体架构

见 [docs/系统架构.md](系统架构.md)。整体为：自然语言 → Agent/Router →
SKILL.md → meeting_tool CLI → 能力模块（FunASR 转写 / 检索 / 定位 / 摘要）
→ 结构化 JSON。安全层与日志层贯穿始终。

## 5. 技术路线

- 语言：Python 3.12
- ASR：FunASR（paraformer-zh + fsmn-vad + ct-punc）
- 检索/定位：纯 Python 实现（正则、区间判断）
- 摘要：jieba 分词 + 抽取式排序（fallback），可选外部 LLM
- GUI：Streamlit
- 测试：pytest

## 6. FunASR 集成

`src/transcribe.py` 延迟导入 `funasr.AutoModel`，加载三模型组合，把输出统一
为 `segments`。已在本机安装 funasr 1.4.16 / torch 2.14.0 / torchaudio 2.11.0，
并验证 `from funasr import AutoModel` 可导入。真实音频转写标记为“待验证”
（`REAL_ASR_TEST = WAITING_FOR_USER_AUDIO`）。

## 7. Skill/Script 设计

SKILL.md 定义 name、description、使用场景、输入输出、CLI 命令、失败处理、
安全边界与示例；Skill 调用真实 CLI 而非 Prompt 模板。CLI 子命令
`transcribe/search/locate/summarize/route` 均可独立运行，退出码 0/非 0 语义清晰。

## 8. 自然语言意图设计

`src/agent_router.py` 用规则把自然语言映射到四类意图：transcribe、search、
locate、summarize。时间格式（HH:MM、HH:MM:SS）与“附近”“X 分钟到 Y 分钟”
均有解析。底层确定性工作不依赖大模型。

## 9. 关键词检索

`src/search.py` 的大小写不敏感子串匹配，返回命中关键词、起止时间、句子及
前后 N 句上下文；支持 `max_results` 截断，不返回整份长文本。

## 10. 时间定位

解析秒、MM:SS、HH:MM:SS；`locate_time` 定位时间点（含越界标记），
`locate_range` 返回区间内所有片段。

## 11. 会议摘要

`src/summarize.py` 输出 topic、summary、key_points、decisions、action_items。
默认抽取式（jieba 关键词 + 句子排序 + 决策/待办关键词），不凭空生成；配置
外部 LLM 后走生成式路径。

## 12. 安全措施

文件白名单（仅 data/input、data/output、logs，只读 examples）、防目录穿越、
覆盖确认（--overwrite）、日志脱敏、不提供删除能力。对应 `src/security.py`。

## 13. 低 Token 优化

“大会议文本检索结果压缩”：先搜索/排序/截取上下文/去重，仅命中片段交给
模型。实测关键词“深度学习”压缩比 0.3472，Token 360 → 125，减少 65.28%。

## 14. 测试设计

29 个 pytest 用例覆盖检索、时间解析、越界、路径穿越、摘要结构、意图识别、
空 transcript、Token 优化等（见 docs/测试报告.md）。

## 15. 实际测试结果

`python -m pytest -q`：**29 passed**，全部通过。

## 16. 遇到的问题

1. funasr 1.4.16 的 PyPI 包未自动安装 torch，导致导入时告警“PyTorch not found”。
2. 直接运行 `python src/meeting_tool.py` 时相对导入失败。
3. 中文摘要关键词初始结果含大量停用词/人名，主题不准确。
4. 本机无 ffmpeg、无真实会议音频。

## 17. 解决方法

1. 显式安装 torch/torchaudio，并在 requirements 中明确；
2. 对 meeting_tool.py 增加“脚本/包”双模式导入兼容；
3. 引入 jieba 分词 + 扩充停用词表 + 注册领域词（深度学习、语音识别等）；
4. ffmpeg 给出明确提示与安装说明；真实转写标记“待验证”，等待用户音频。

## 18. 总结

完成了从 FunASR 集成、检索/定位/摘要、安全与日志、低 Token 优化到
Skill/CLI 接口、GUI 与自动化测试的完整链路，满足课程验收要求。真实音频
转写与外部 LLM 摘要待用户提供音频与密钥后即可启用。
